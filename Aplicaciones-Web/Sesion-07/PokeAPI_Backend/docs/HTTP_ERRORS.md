# HTTP Status Codes and Error Handling

## PokeAPI Backend Project

This document explains the HTTP status codes and network exceptions that may occur when the Python application communicates with PokeAPI.

---

## 1. HTTP Status Code 200 - OK

**Meaning:**  
The request was successful.

When the program sends a valid Pokémon name to PokeAPI and the server successfully finds the Pokémon, the API returns HTTP status code **200**.

Example:

```text
HTTP Status Code: 200
```

The program can then safely convert the JSON response into a Python dictionary and process the requested information.

---

## 2. HTTP Status Code 400 - Bad Request

**Meaning:**  
The server cannot process the request because the request is malformed or contains invalid information.

Possible causes include:

- Incorrect query parameters.
- Invalid URL structure.
- Invalid request syntax.

Example:

```text
HTTP Status Code: 400
```

---

## 3. HTTP Status Code 401 - Unauthorized

**Meaning:**  
Authentication is required and the client did not provide valid credentials.

Example:

```text
HTTP Status Code: 401
```

This project normally does not receive this error because the PokeAPI endpoints used here are public and do **not** require an API Key.

---

## 4. HTTP Status Code 403 - Forbidden

**Meaning:**  
The server understood the request, but it refuses to authorize access to the requested resource.

Example:

```text
HTTP Status Code: 403
```

---

## 5. HTTP Status Code 404 - Not Found

**Meaning:**  
The requested resource does not exist.

This is one of the most important errors for this project.

For example, if the user enters:

```text
pikachuxyz
```

PokeAPI cannot find a Pokémon with that name and can return:

```text
HTTP Status Code: 404
```

The program handles this case and informs the user that the Pokémon was not found.

---

## 6. HTTP Status Code 408 - Request Timeout

**Meaning:**  
The server timed out while waiting for the complete request.

Example:

```text
HTTP Status Code: 408
```

This is an HTTP response generated by a server. It is different from the Python `Timeout` exception, which can be raised by the `requests` library when the configured waiting time is exceeded.

---

## 7. HTTP Status Code 429 - Too Many Requests

**Meaning:**  
The client has sent too many requests in a certain period of time.

Example:

```text
HTTP Status Code: 429
```

An API can use this response to enforce rate limits.

---

## 8. HTTP Status Code 500 - Internal Server Error

**Meaning:**  
An unexpected error occurred on the API server.

Example:

```text
HTTP Status Code: 500
```

This usually represents a server-side problem rather than an error in the Python program.

---

## 9. HTTP Status Code 502 - Bad Gateway

**Meaning:**  
A gateway or proxy server received an invalid response from another server.

Example:

```text
HTTP Status Code: 502
```

---

## 10. HTTP Status Code 503 - Service Unavailable

**Meaning:**  
The server is temporarily unavailable.

Possible reasons include:

- Server maintenance.
- Temporary overload.
- Service interruption.

Example:

```text
HTTP Status Code: 503
```

---

## 11. HTTP Status Code 504 - Gateway Timeout

**Meaning:**  
A gateway or proxy did not receive a response from another server within the allowed time.

Example:

```text
HTTP Status Code: 504
```

---

# HTTP Status Code Categories

HTTP status codes are grouped by their first digit:

| Range | Category | Meaning |
|---|---|---|
| 100-199 | Informational | The request is still being processed or additional information is being communicated. |
| 200-299 | Success | The request was received and processed successfully. |
| 300-399 | Redirection | Additional action may be required to complete the request. |
| 400-499 | Client Error | The request contains a problem or requests a resource that is unavailable to the client. |
| 500-599 | Server Error | The server failed while processing a valid request. |

---

# Why `raise_for_status()` Is Used

The main project contains:

```python
respuesta.raise_for_status()
```

If the HTTP response has a successful status such as **200**, execution continues normally.

If the API returns an error in the **4xx** or **5xx** range, `raise_for_status()` generates a `requests.exceptions.HTTPError` exception.

This allows the application to separate successful responses from HTTP errors.

---

# Network Exceptions Used in the Project

## Timeout

Handled with:

```python
except requests.exceptions.Timeout:
```

The request uses:

```python
requests.get(url, timeout=10)
```

If PokeAPI does not respond within the configured waiting time, the program catches the timeout instead of waiting indefinitely.

---

## ConnectionError

Handled with:

```python
except requests.exceptions.ConnectionError:
```

This can occur when the computer has no Internet connection, DNS resolution fails, or a connection to the server cannot be established.

---

## HTTPError

Handled with:

```python
except requests.exceptions.HTTPError as error:
```

This exception can be raised by:

```python
respuesta.raise_for_status()
```

It represents HTTP error responses such as **404**, **500**, or other 4xx/5xx responses.

---

## RequestException

Handled with:

```python
except requests.exceptions.RequestException as error:
```

`RequestException` is the base exception used by the `requests` library for request-related problems.

It works as a final safety net for network errors that were not already handled by the more specific exception blocks.

---

# Why PokeAPI Does Not Need an API Key

Some APIs require authentication with an API Key, token, username/password, or OAuth.

The public PokeAPI endpoints used in this project do not require an API Key for normal read requests.

That is why this request works directly:

```python
requests.get(
    "https://pokeapi.co/api/v2/pokemon/pikachu",
    timeout=10
)
```

No secret key is added to the URL, HTTP headers, or query parameters.

---

# Example Error Flow

If the user enters a Pokémon name that does not exist:

```text
User input
   |
   v
HTTP GET request
   |
   v
PokeAPI returns 404
   |
   v
raise_for_status()
   |
   v
HTTPError exception
   |
   v
Program displays a controlled error message
```

This prevents the program from attempting to process invalid JSON data as if the request had succeeded.

# Summary

The PokeAPI backend project demonstrates both successful REST API consumption and proper error handling.

The most relevant concepts are:

- **200** means the request succeeded.
- **404** means the requested Pokémon was not found.
- **4xx** responses represent client-side request errors.
- **5xx** responses represent server-side failures.
- `raise_for_status()` converts 4xx/5xx responses into `HTTPError`.
- `Timeout` protects the application from waiting indefinitely.
- `ConnectionError` handles connection failures.
- `RequestException` provides a general fallback for request-related errors.
